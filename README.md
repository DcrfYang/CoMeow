## 在 mgmp 之上新增的内容

- **联机大厅**：在标题界面通过信令服务器创建或加入房间，支持房间密码、房间搜索，房主可以锁定房间。房间列表里，24 小时内加入过的房间、以及同一房主的其他房间会排在最前面并高亮显示。
- **三种连接方式（房主建房时选择）**：TCP 直连、Steam 中继、服务器转发；直连需要房主的端口能被外网连上，建房前 mod 会自动检测并提示（见下文“在线联机的网络要求”）。
- **以同步为主的战斗**：不再要求两端的随机数种子/抽取次数完全一致，而是在每个同步点（包括每个角色的每一次行动前）把随机流对齐，房主每个回合发布一次棋盘状态，其他玩家的对应数据被直接纠正（见下文“它是怎么工作的”）。战斗期间，两端的技能、被动、物品、职业等“解锁内容”也按房主的存档回答，保证抽到同样的技能；战斗一结束就换回各自存档的，升级用的是自己的。
- **局域网联机（不需要服务器）**：大厅服务器的代码也编进了 mod 本身。房主在“局域网”页直接建房，同一网络里的朋友用“搜索局域网房间”找到并加入（UDP 广播发现，端口 27701；也可以手动输入房主的局域网地址）。
- **每名玩家带自己的猫**：采用会话克隆，战斗结束后合并回原来的猫；章节和主线道具由房主决定。房主可以携带剧情类道具，客户端不能；房主在剧情事件里做的选择，其结果（剧情标记、任务进度、解锁、事件给的道具）只记在房主自己的存档里，不会改写客户端的存档。
- **联机难度**：联机时敌人的生命值和护甲翻倍；3 人房间每人最多带 3 只猫，4 人房间每人最多带 2 只。
- **房主决策**：游戏中的大多数决策由房主做出，其他玩家跟随房主。随机事件两端看到的是同一个事件，由房主选择；受技术限制，事件的效果只会落在房主的猫上。
- **存档保护**：标题界面内置存档备份与恢复（20 个位置，可以导入、导出）。另有 3 个“自动存档”：每次结算完成、回到仓库时自动存入，最旧的会被新的替换，只能读取或导出，不能覆盖或删除。
- **同步存档**：联机时每走完一个节点，两端都会各存一份“同步存档”，整局都保留，打完大头目之后的那一份会有标记；读取较早的同步存档不会删掉比它新的。出现不同步时，可以读取之前的同步存档，走不同的路径继续。
- **房间聊天**：在房间里按**回车**打开输入框（同时显示全部历史，这时键盘和鼠标不会传给游戏），再按一次回车发送，所有人的屏幕上会显示聊天记录 10 秒后淡出；输入框是空的时回车只是关闭它，Esc 取消。名字的颜色与房间面板里的 P1～P4 一致。
- **不同步的处理**：仅状态上的细小差异会等下一个回合再判断，必要时由房主的棋盘直接纠正；随机数或队列对不上则立即暂停（HALT）。每次出现不一致，游戏都会弹出“是否上传日志”的窗口。暂停后会提示该怎么办，并且每隔 2 秒自动击杀场上所有敌人，直到战斗结束，然后自动解除暂停，可以继续走下一个节点。
- **问题反馈**：游戏中按 **F2** 打开面板，把当前日志和问题描述上传到收集日志的服务器。出现不同步时，两端会把各自日志的关键部分互相发送，所以只要有一位玩家上传，就能同时看到两端的情况。
- **服务器**：同一份源码可以在 Windows 和 Linux 上构建（见 `server/`，Linux 说明见 `server/linux/README.md`）。
- **多语言界面**：支持十种语言。

当前为**测试版**，可能出现坏档等问题，请务必先备份存档。

**游戏美术资源不在本仓库中。** `assets/` 里的界面图片和字体需要用 `tools/export_ui_assets.py` 从你自己的游戏文件导出；
缺少这些资源时，mod 会退回到简单图形和系统字体，功能不受影响。

## 已知限制

- 这是测试版，可能出现坏档等问题，请先备份存档。
- 3 人和 4 人联机目前测试得很少；2 人联机已经连续完整打通多个章节，没有出现不同步。
- 客户端不能携带剧情类道具；房主可以带，但事件给的道具和任务进度只算在房主的存档里。
- 随机事件的效果只会落在房主的猫上。
- 目前 mod 允许房主带领客户端进入客户端尚未解锁的区域，但可能产生未知的影响，不建议这么做。
- 游戏里所有“新猫入队”的效果较大概率导致异常，可以在 mod 设置里禁用。
- 游戏版本更新之后，需要等 mod 适配新版本（见下文“游戏更新之后”）。

## 更新

下载的文件夹里带有更新器（`CoMeow-Updater.exe`）。每次运行 `CoMeow.exe`，它会先向服务器（`mgmp.json` 里 `signal.addr`，80 端口）查询最新版本，和本地文件逐个比较；有变化就启动更新器并关闭自己，
更新器只下载有变化的文件（校验 SHA-256 后才替换；你自己的 `mgmp.json` 不会被覆盖），完成后提示重新打开 `CoMeow.exe`。更新器本身不会自动更新：如果提示“更新器需要升级”，请重新下载并解压整个压缩包。
不想检查更新时用 `CoMeow.exe /noupdate` 启动。

## 设置

所有设置都在加载器旁边的 `mgmp.json` 里。

| 设置 | 作用 |
|---|---|
| `game` | `Mewgenics.exe` 的完整路径 |
| `log` | 日志文件名 |
| `signal.addr` / `signal.port` | 在线大厅服务器的地址和端口（默认 27700）。局域网联机用不到它 |
| `signal.name` | 大厅里显示的玩家名，留空则用电脑名 |
| `signal.room` | 填了就自动创建或加入同名房间，留空则在大厅里手动选择 |
| `signal.auto_connect` | 启动时是否自动连接服务器 |
| `signal.legacy_role` | 是否保留启动时用 `net.role` 指定身份的旧方式 |
| `net.role` | `off`、`host` 或 `client`（只有开启 `signal.legacy_role` 时才生效） |
| `net.addr` / `net.port` | 游戏连接的地址和端口，默认 `27600` |
| `net.control` | 你控制哪些猫。保持 `"auto"` 即可，它会自己平均分配。 |
| `ui.enabled` | 调试面板是否存在 |
| `ui.visible` | 面板是否一开始就显示 |
| `ui.key` | 切换面板的按键，默认 `F1` |
| `ui.beta_notice` | 是否显示首次运行的测试版提示框 |
| `ui.dev_tools` | 开发者开关总闸，默认关闭，玩家请勿开启 |

`debug` 部分是给开发用的，最好不要动。其中 `record` 会让 mod 记录大量关于游戏随机数生成器的细节，
追查 bug 时有用，其余时候纯属额外开销。没有打开 `ui.dev_tools` 时，所有开发者开关都会被忽略。

只有真正打算让你修改的设置才放在这个文件里，其余的都是 `src/core/mgmp_tuning.h` 里的编译期常量，
每一个都附有说明，解释了为什么不对用户开放。

## 在线联机的网络要求

大厅服务器负责“牵线”；游戏数据走哪条通道，**由房主在创建房间时选择**（创建区的“连接方式”一行），加入者不用选，会自动按房主选的方式连：

- **TCP 直连（默认 27600）**：延迟最低，但房主的 27600 端口必须能被外网连上。
  - 连上大厅服务器后，mod 会先在本机临时监听该端口、请路由器转发（UPnP），再让服务器从外网试连一次（预检）。通了才能选“直连”；不通会提示“请在路由器中转发 TCP 27600（或开启 UPnP）”，点“重新检测”可再试；端口被本机其他程序占用时也会提示。
  - 加入者会按顺序尝试服务器给出的地址，每个地址最多等 5 秒；全部失败时会提示原因并退出房间。
  - 同一个路由器后面的玩家（和房主公网 IP 相同）会收到房主的内网地址，内网地址连不上时再退回公网地址。
- **Steam 中继（不用转发端口）**：需要房主和加入者都运行 Steam，并登录各自的账号。mod 通过游戏已加载的 `steam_api64.dll` 使用 Steam 的点对点网络，能打通 NAT 时直连，打不通时由 Valve 的中继服务器转发；游戏数据仍是原来的 TCP 协议，只是换了一层承载。
  - 这条通道有时会失败（日志里是“结束原因 5001：Bad cert … is not known to us”，原因是房主这边的 Steam 网络配置较旧）。mod 会在失败后请房主反向拨号再试一次；日志里的 `STEAMNET` 行记录 Steam 网络状态。
  - 可以在 `mgmp.json` 的 `net.steam` 里关闭（默认开启）。
- **服务器转发**：大厅服务器把双方的 TCP 字节原样转发，不需要开放端口也不需要 Steam，但服务器带宽有限：同一台服务器同时最多 10 个转发房间（超出会被拒绝），每个房间限速，只建议在前两种方式都不可用时选择。选它时，如果连的是作者的公共服务器，会先弹出提示。
- 其余情况：不在同一网络、又没法转发端口的朋友，也可以用虚拟局域网软件（ZeroTier、Radmin VPN 等）组网后走“局域网”页。

## 局域网联机

在标题界面点“多人联机”，切到“**局域网**”页：

- **房主**：填房间名（可选密码），点“创建局域网房间”。mod 会在你的游戏进程里启动一个大厅（TCP 27700，被占用时依次尝试 27702、27703），并用它建房。房间界面会显示你的局域网地址。
- **其他人**：点“搜索局域网房间”，列表里选择房间加入。搜索用 UDP 广播（端口 27701），所以要在同一个网段里；搜不到时，让房主告知局域网地址（形如 `192.168.1.5:27700`），在“在线服务器”页手动输入。
- 房主退出房间或断开后，这个大厅就会自动关闭。游戏本身的连接仍然是玩家之间的 TCP 直连（27600）。
- 第一次建房时 Windows 防火墙可能会弹窗，请允许（专用网络）；如果队友连不上，先检查这一项。
- 服务器端的“收集日志”功能在局域网大厅里是关闭的。

## 游戏更新之后

mod 的挂接点是按固定的游戏版本测量出来的。它会用字节特征尽量在补丁后自己重新定位，但如果游戏的可执行文件和 mod 预期的版本不同，
mod 会拒绝挂接，以免在结构已经变化的游戏上悄悄损坏数据，并在日志里说明原因。游戏大版本更新后，需要等 mod 适配新版本。

## 它是怎么工作的，简述

**这个 mod 不再要求两台机器的随机数种子或抽取次数一模一样，而是主动做同步。** 早期版本假设“同样的起始局面 + 同样的点击 = 同样的结果”，
让两台机器各自演算；但游戏里有四百多处随机抽取点，只要某一端多抽或少抽一次、或者两端本地存档/队伍略有不同，之后所有的随机结果就会整体错位。
现在的做法是三层：

**1. 在每个同步点把随机流对齐。** 战斗构建的每个阶段、选关、每个事件的随机处理（属性检定、随机奖励、抽物品等）、每个回合开始和每个角色的每一次行动前，各端都把模拟用的随机流重设成由（战斗/节点、序号、角色、第几次行动）推出的同一个值，不管之前各端抽过多少次，也不管某一端的玩家在两次行动之间做了什么（比如预览技能范围）。分歧最多存活到下一个同步点，不会累积。

**2. 把会被“一次性随机”决定的状态直接同步。** 房主每个回合发送棋盘状态（生命、护盾、位置、朝向、行动顺序、单位的种类等），其他玩家的对应数据被直接覆盖成房主的，玩家猫的生命、护盾、位置、朝向也一样；每个玩家点击了什么（行动）仍然发送，两端各自演算过程，结果有偏差时由棋盘同步纠正。战斗里新出现、被移除或变身的单位，也按房主的为准。

**3. 战斗之外的一切由房主决定，再把结果发过去。** 地图、商店、升级和事件的选择、进入节点用的种子、每只猫的数据（按“猫的归属者”为准，用摘要校验并自动修复）都由房主做主；游戏本身就知道怎么把一只猫、一份背包和一局的历史写到磁盘上，所以这些可以整块传送。背包是每个人独立的，不同步。两个玩家的存档解锁内容通常不同（能抽到的技能、职业、事件里的计数器），所以战斗和事件期间，这些“解锁查询”都按房主的存档回答，结束后换回自己的，客户端自己的存档不会因此被写入房主的进度。

这些仍然会被不断检查：每场战斗的每个回合，以及每次进入地图节点时，两台机器都会交换各自状态的指纹并比对；每个动作里抽了多少次随机数、每个单位的属性和行动顺序，也会各自记下并互相比对，不一致就在日志里指出是哪里，严重时暂停战斗（HALT）。单人游戏不受影响，同步只在房间里生效。实现细节见 `src/session/` 里的注释。

技术细节，包括地址、结构偏移、测量数据和走过的弯路，都写在源码的注释里，紧挨着它所解释的代码。

## 项目结构

```
src/core/          加载、挂接、日志、配置、崩溃报告
src/determinism/   随机数跟踪、录制与回放
src/net/           网络传输、消息格式、大厅客户端与日志上传
src/session/       真正让两个游戏保持同步的一切
src/ui/            面向玩家的菜单、调试面板和屏幕上的覆盖层
loader/            mgmp_loader.exe
server/            大厅与日志收集服务器（Windows 和 Linux 同一份源码）
tests/             可以单独测试的逻辑的单元测试
tools/             开发过程中用到的 Python 和 PowerShell 辅助脚本
third_party/       Dear ImGui、MinHook、stb_image、nlohmann/json
```

运行测试：

```powershell
ctest --test-dir build --build-config Release
```
